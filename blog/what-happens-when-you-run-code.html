What actually happens when you run code

6 min read

You type print("hi"), press run, and text appears. It feels like magic, but there are only a few steps, and every language shares them.

1. Your code is just text

A source file is plain text. A computer's processor cannot read it. A processor only understands machine code: long lists of tiny numbered instructions like "add these two numbers" or "copy this value to that place in memory."

2. Something has to translate it

Translation happens in one of three ways:

  • Compiling: a program called a compiler translates all your code into machine code before it runs. You get a separate program file. C, C++, Rust and Go work this way.
  • Interpreting: a program called an interpreter reads your code and does what it says, step by step. Python and Ruby work this way.
  • Mixed: the code is first compiled to a simpler middle form, then run by a virtual machine. Java does this. JavaScript engines go further and compile the busiest parts to machine code while the program runs. This is called just-in-time (JIT) compilation.

3. Parsing: understanding the text

Before running anything, the translator breaks your text into pieces (tokens like print, (, "hi") and builds a tree that shows how they fit together. 2 + 3 * 4 becomes a tree where the multiplication sits lower, so it runs first. This is why a missing bracket gives a "syntax error": the tree cannot be built.

4. Running: memory and the stack

While a program runs, it keeps data in memory. Each time you call a function, the computer adds a new block to a pile called the call stack holding that function's variables. When the function ends, its block is removed. If a function keeps calling itself forever, the pile grows until it overflows. That is a "stack overflow."

def countdown(n):
    if n == 0:
        return
    print(n)
    countdown(n - 1)   # adds a new block to the stack

countdown(3)

Larger or longer-lived data goes in a second area called the heap. Who cleans the heap up is a big difference between languages, which the next post covers.

5. The result

The processor runs billions of these tiny instructions every second. Your text becomes a tree, then instructions, then changes to memory, then pixels on your screen.
